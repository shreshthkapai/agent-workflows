# Engineering guidance

Follow the user's scope and the host's global and project instructions. Installed invocation metadata controls which workflows may be selected automatically.

- Prefer the smallest complete change and model the data before logic.
- Preserve required contracts and compatibility; investigate root causes rather than hiding symptoms.
- Define observable completion against the affected artifact. Report commands, results, failures, and evidence gaps honestly.
- Use one primary workflow and relevant supporting principles. Do not read every skill or start extra panels merely because they are installed.
- Keep implementation delegates bounded, give them the applicable instructions and skill paths, and inspect their actual artifacts. Workers do not start nested workflows or spawn agents.
- Isolate concurrent writers and combine selected results sequentially. Instructions to take turns do not provide synchronization.
- Read `{{RUNTIME_GUIDE}}` before runtime-specific operations. Missing capabilities are limitations to report, not permission to invent execution.
- Routine reversible steps within an authorized task can proceed. Skill activation does not authorize unrelated configuration changes, testing, messages, commits, publication, or deployment.

Detailed operational rules: `{{WORKFLOW_RULES}}`. Model-role registry: `{{MODEL_REGISTRY}}`. Neither is native host configuration.
